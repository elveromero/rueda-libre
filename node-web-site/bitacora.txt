6. ROLES DE LAS TECNOLOGÍAS WEB EN EL PROYECTO (HTML, CSS Y JAVASCRIPT):

- HTML (HyperText Markup Language):
  * Rol: Es el esqueleto y la estructura semántica de la página web. Define los elementos principales como encabezados, párrafos, tablas de tarifas e imágenes.
  * Ejemplo concreto: La etiqueta <table> con sus <thead>, <tbody> y <th scope="col"> utilizada para estructurar de manera accesible la lista de precios de alquiler en "tarifas.html".

- CSS (Cascading Style Sheets):
  * Rol: Es la capa de diseño visual y presentación. Se encarga de dar estilo, colores, tipografías, distribución (layouts) y adaptabilidad (diseño responsivo) para que el sitio luzca profesional.
  * Ejemplo concreto: Aplicar una regla de color corporativo verde oscuro (#1b4d3e) al fondo de la barra de navegación y configurar las tarjetas de los tours para que se adapten a pantallas de celulares y computadoras.

- JavaScript:
  * Rol: Es el motor de interactividad y comportamiento dinámico del sitio. Permite reaccionar a las acciones del usuario en tiempo real sin necesidad de recargar la página completa.
  * Ejemplo concreto: Un script que calcule automáticamente el costo total de un alquiler de bicicletas al seleccionar la cantidad de horas en un formulario interactivo y muestre el precio en tiempo real.

8. DISEÑO DE REGIONES Y SEMÁNTICA (v0.2):

- Esquema de regiones por página:
  * index.html: <header> (Logo, H1, Nav), <main> (Secciones temáticas y Artículos de servicios), <footer> (Pie de página).
  * paginas/tarifas.html: <header> (Logo, Nav), <main> (Secciones de tablas, notas de cliente) + <aside> (Contenido complementario: qué llevar), <footer>.
  * paginas/reservas.html: <header> (Logo, Nav), <main> (Sección de reservas) + <aside> (Horario de atención detallado en lista de definiciones), <footer>.

- Uso de div y span:
  * Se eliminaron todos los contenedores genéricos innecesarios, reemplazándolos por etiquetas nativas semánticas (<header>, <main>, <section>, <article>, <aside>, <footer>). No se requirió mantener ningún div estructural genérico ya que la jerarquía semántica cubre el 100% del layout actual.

  9. JUSTIFICACIÓN DE CONTROLES DEL FORMULARIO DE RESERVA:

- Correo electrónico (<input type="email">):
  * Justificación: Se eligió este tipo de campo porque incorpora validación nativa del navegador, asegurando que el texto ingresado cumpla con la estructura estándar de una dirección de correo electrónico (presencia de "@" y dominio), reduciendo errores de captura.

- Fecha de reserva (<input type="date">):
  * Justificación: Facilita la experiencia de usuario (UX) al desplegar un calendario gráfico interactivo nativo, evitando que el usuario deba digitar manualmente la fecha con un formato específico y previniendo entradas inválidas.

- Tipo de bicicleta (<input type="radio">):
  * Justificación: Es la opción más adecuada ya que las alternativas son mutuamente excluyentes (el usuario solo puede elegir una bicicleta a la vez). Al compartir el mismo atributo 'name', el navegador restringe la selección a una sola opción de manera visual y lógica.

11. AUDITORÍA DE ACCESIBILIDAD Y CORRECCIONES (v0.2):

- Hallazgo 1 (Imágenes): En algunas páginas había imágenes con atributos 'alt' genéricos ("imagen", "foto").
  * Corrección: Se actualizaron para ser estrictamente descriptivos según el contexto (ej. alt="Logo de Rueda Libre Medellín" y alt="Bicicleta urbana equipada con casco").
- Hallazgo 2 (Enlaces fuera de contexto): Había enlaces con textos ambiguos como "Ver más" o "Clic aquí".
  * Corrección: Se reescribieron los textos de enlace para que tengan sentido por sí mismos (ej. "Ver tabla completa de recorridos guiados y precios").
- Hallazgo 3 (Jerarquía de encabezados): Riesgo de salto de nivel de título en secciones secundarias.
  * Corrección: Se aseguró una estructura estrictamente descendente (un único <h1>, seguido de <h2> para secciones y <h3> para subsecciones/artículos).
- Hallazgo 4 (Idioma del documento): La etiqueta raíz carecía de especificación de idioma o presentaba ambigüedades.
  * Corrección: Se verificó e impuso uniformemente la propiedad <html lang="es"> en las tres páginas del sitio.
- Hallazgo 5 (Navegación por teclado y foco): Algunos elementos interactivos y campos de formulario no garantizaban un orden lógico de tabulación secuencial.
  * Corrección: Se reorganizó la secuencia de elementos en el DOM para permitir una navegación fluida mediante la tecla Tab y Shift + Tab sin saltos extraños.
